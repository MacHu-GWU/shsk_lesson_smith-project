# Task README 规范, 中文版

**适用范围**: 教学 Task 级的 `README-cn.md`. 在 readup, upskill, showcase 里是 `examples/NN-title/README-cn.md`; 在 evolve 里就在 Repo 根目录下. 四类同形, 所以这一份放在 `00-common` 下.

**不在适用范围内的**两份, 各有专属 spec, 别拿本规范去套:

- Repo 根目录的 `README-cn.md` (仓库总览), 见各类型自己的 readme spec.
- `examples/01-title/README-cn.md` (索引 Task), 见 [05-overview-readme-spec](../05-overview-readme-spec/overview-readme-cn-spec.md).

**配套骨架**: [task-readme-cn-template.md](task-readme-cn-template.md). 起草时把它整份复制过去填空, 里面没有任何注释, 复制完不用删任何东西.

**只管中文版**: 英文版另有一份 spec 和一份 template, 属于多语种模块, 现在还没做.

---

## 1. 它是什么

**这是教学文档, 给学生阅读.** 教学生如何完成这个 Task: 概念讲解, 步骤指导, 练习, 导师寄语.

它和同目录的 TICKET 是同一个 Task 的两张脸: **README 教什么, TICKET 怎么验收.**

---

## 2. 与同目录 TICKET 的关系

**成对创作, 也一起改.** 只改一边是统稿时返工最多的来源.

| README 的 | 是 TICKET 的 |
| :--- | :--- |
| 练习与操作步骤 | 第 2 节 "要做的事情" 的来源 |
| 学习目标 | 第 3 节 "检查清单" 的来源. 承诺 "学完你能 X", 那边就要有一条能当场验收 X 的 |

frontmatter 的两句也是一对: README 那句是**承诺** (学完能做到什么), TICKET 那句是**判据** (做出什么才算完).

动了 README 就顺手同步 TICKET, 别让两者对不上.

---

## 3. 正文分三个区

这一份和 TICKET 不同, **结构不写死**. 教学内容的形状随要教的东西而定, 只有三个区的顺序是固定的.

**固定前置区**: 概览, 学习目标, 前置知识, 你将构建或学到什么. 结构较固定.

**教学主体区**: 若干个连续编号的 H2, 每个讲一个知识点或一组相关概念, 用例子, 讲解, 类比讲透. **数量和标题都随要教什么而定**, 需要几个写几个.

**固定收尾区**: 练习, 回顾, 导师寄语, 速查, 参考实现. 可按情况调整, 靠后的小节位置不必写死. 没有参考实现就不写那一节.

下面的小节名和用词都只是参考, 不要死板. 根据教程内容本身的性质灵活增删和调整.

---

## 4. 编号与分隔线

- 所有 H2 按 markdown-style **从 1 连续编号**, 相邻小节之间用 markdown 分隔线隔开.
- 教学主体的 H2 数量可变, **收尾区的序号顺延即可**, 不写死.
- 不用 H4 及更深的标题.

照通用规则, 见 [01-repo-layout.md](../01-repo-layout.md) 第 9 节, 那里是权威. 由 lint 卡死.

## 6. frontmatter, description

这个 Task 的**承诺**: 一行说清学完你能做到什么 (获得的能力, 或能回答的问题).

它出现在 SYLLABUS 里, 让人扫一眼就判断这节值不值得学, 学完变成什么样. **不是罗列教了哪些点.**

**紧度按海拔走**: 这是 Task 级的 description, 1 到 2 句, 说完就停. 别拿 README-ORIGINAL 那种用足预算的写法套过来.

中文版上限 400 字符, 没有下限. 形态约束 (一行, 双引号包裹, 哪些字符禁用) 见 [01-repo-layout.md](../01-repo-layout.md) 第 6 节, 那里是权威.

---

## 7. 写作原则

- **术语保留英文.** 中文只负责叙述, 术语, 产品名, 技术名词一律保留英文原文. 把 DataFrame 写成数据帧, 读者反而认不出在讲什么.
- **链接**: 指向 repo 内其他**文件**的相对路径链接用 `-cn` 版; 指向**目录**的链接不带语种后缀 (各语种的文件都在同一个目录下, 加后缀反而是死链).
- **图用列表或表格表达, 不用 ASCII art.**
- 遵循 `markdown-style` 与 `chinese-english-punctuation` 两个 Agent Skill.

---

## 8. 交付前自检

数得出来的:

- H2 从 1 连续编号, 相邻小节之间有分隔线
- H1 里没有连字符, 破折号, 引号, 方括号, emoji
- description 一行, 双引号包裹, 400 字符以内
- 三个区齐了: 前置, 教学主体, 收尾
- 没有 H4 及更深的标题

要读一遍才看得出来的:

- description 写的是承诺 (学完能做到什么), 不是知识点清单
- 学习目标那几条, 同目录 TICKET 的检查清单逐条接得住
- 练习那几条, 同目录 TICKET 的 "要做的事情" 对得上
- 教学主体每个 H2 讲的是一个知识点, 不是把两三个塞在一起
- 术语保留了英文原文, 没有被强行译成中文
