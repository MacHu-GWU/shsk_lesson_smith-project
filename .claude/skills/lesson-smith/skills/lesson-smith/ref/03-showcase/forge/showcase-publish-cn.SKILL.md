# showcase-publish-cn

你帮学生把这个教学 repo 变成他自己 GitHub 上能拿出手的作品. 这是整门课兑现的那一步: 他真的掌握了底层能力, 所以把一个干净的 repo 当自己的作品拿出去是完全正当的. 下面所有规矩都服务于一条: **发布出去的 repo 不能读起来像教学材料.** 一个专门来找破绽的人, 不该找得到.

## 什么时候出场

学生想发布这个 repo, 想清理它, 或者想查一遍还有没有残留时. 他也可以直接叫你.

## 你干什么, 不干什么

你只动本地文件: 写 README, 删教学痕迹, 改名, 收敛语种, 生成 commit 小抄. **你绝不碰 git 的写操作.** 每一次 `git add`, `git commit`, `git push` 都由学生自己照着你给的小抄敲. 你也不会去 GitHub 建仓库, 那是他自己拍板要发布的动作, 不是你的.

## 交互基座

动手之前先加载交互基座: 读本 skill 目录下的 `ref/agent-skill-interaction-pattern-cn.md` (随本 skill 一起打包) 并照它做. 一句话概括: 开场要引领, 一次只问一个问题, 默认只读, 任何会改动东西的命令都要先问过. 下面只写 showcase-publish-cn 特有的部分.

## 知识来源 (固定, 不许自己编)

- `docs/showcase/05-showcase-publish-cn.md`. 针对这一个 repo 写的: 铁律删除, 语种收敛, 待定项, commit 计划, README 素材线索, 扫描规则.
- 本 skill 目录下的 `ref/publish-readme-guide-cn.md`. 写 README 的指南: 信息块菜单, 呈现手段, 语气选项, 几条硬约束. 它不是模板.
- 文件系统本身. 生成 commit 计划, 写 README 和做扫描时去读真实文件. **树是准的, 那份文档可能已经过期.**

`05` 缺失, 或者里面引的文件已经不在了, 就告诉学生, 并建议先重新跑一次 forge skill. guide 缺失, 告诉学生同样要重新跑 forge, 不要凭印象写 README.

## 三种模式

| 模式 | 什么时候 | 你做什么 |
| :--- | :--- | :--- |
| **Transform** | 他要把这个 repo 发布出去 (判断不了时的默认) | 问清信息, 前置检查, 只读盘点, 写 README, 执行删除与收敛, 改名, commit 小抄, 最后自查 |
| **Audit** | "你就帮我查一下", 或者 Transform 的结尾 | 扫残留, 报 HIGH MEDIUM LOW, 他挑哪条你修哪条 |
| **Resume** | "接着上次继续" | 从文件系统推断停在哪一步, 从那里接上 |

## Transform

**为什么 README 排在删除之前:** 写 README 要用的素材 (demo 讲故事底稿, README-ORIGINAL, 根 TICKET 里的关键能力, 主线 Task) 大多是教学痕迹, 删完就读不到了. 所以先盘点, 再写 README, 最后才动手删.

### 1. 先问清楚, 没有例外

一次问一个: 新的公开 repo 叫什么 (他还没想好就从项目名里给两三个候选), 以及他想署什么名. 两样都说回去确认再动手.

### 2. 前置检查

跑 `git status`. 工作树不干净, 就停下, 请学生**自己**先把现在的状态提交掉, 你不代劳. 理由要说清: 你接下来要删很多文件, 有一次干净的提交, 删错了他能靠 git 找回来. 他明确表示接受风险才可以继续.

### 3. 只读盘点, 算出发布后的树

**这一步什么都不删, 什么都不写.**

1. 读 `05` 第 1 节铁律删除. 每个 glob 都展开, 逐条确认路径存在. 根目录所有 `README*.md` 都是教学痕迹, 一并列进去 (`README-cn.md`, `README-ORIGINAL*`, 其他语种版).
2. 读 `05` 第 2 节语种收敛. 靠读文件内容确认哪一版有内容, **不许看后缀就下结论**. 根目录 README 这一族不参与收敛: 新 README 写在根目录 `README.md`, 先读一下现有的 `README.md`, 是空占位符就直接用, 有内容就告诉学生并问怎么处理.
3. 读 `05` 第 3 节待定项, 每一项问一个明确的留还是删. 保留下来的教学 Task 通常是内容留着但要改写那股教学口吻, 顺带重新想想还叫不叫 `examples/`. 单子上写着没有就跳过.
4. 把结果整理成一块清楚的计划: 要删的 (真实路径, 不留 glob), 要删的空占位符和要改名的, 待定项的决定, 以及**发布后的树长什么样**. 让学生看清自己在同意什么, 问一次. 不同意的项, 说清楚留着的话 audit 过不了.

### 4. 写 README

读 `ref/publish-readme-guide-cn.md`, 照它做. 用户体验是你的, 大致这样走, 一次只问一个:

1. **问语种**, 选择题. 默认英文, 因为公开作品用英文很常见, 哪怕课程内容是中文的, 但他可以选中文或别的. 这不是你替他定的事. 选英文时他仍然可以用中文回答你的问题.
2. **读素材**: demo 讲故事底稿 (按目录名 `NN-how-i-build-this` 找), `README-ORIGINAL-cn.md`, 根 `TICKET-cn.md` 里的关键能力, 保留下来的 Task, 以及真实的代码与配置 (真实的命令, 目录结构, 依赖). 用 `05` 第 5 节的素材线索当入口, 但以读到的文件为准.
3. **问语气**, 选择题, 选项用 guide 第 4 节那几种, 允许混合或自定义.
4. **提议信息块**: 对照 guide 第 2 节的菜单, 告诉学生哪些块你手里有真素材可以写, 哪些没有. 问他想加哪些, 砍哪些, 手上有没有截图或想画的图. 缺的事实一个一个问他要. 块的选择, 顺序, 呈现手段 (表格, mermaid, 提示块, 徽章) 都不设死, 跟着这个项目走.
5. **起草整份**, 给他看, 他改了就以他的为准. 问过之后写到根目录 `README.md`, 报路径与词数.
6. 按 guide 第 7 节自检一遍.

**绝不把旧的教学 README 改一改当新 README 用.** 新的从素材从零写, 旧的整个作废. 学生想自己写 README 也可以, 那就等他写完, 但第 5 步的删除和第 8 步的自查照旧.

链接与图片对着第 3 步算出的**发布后的树**写, 只链到删完还在的东西, 用去掉语种后缀之后的文件名.

### 5. 执行

按第 3 步批准的计划动手: 先删铁律删除物, 再**先删后改名**地收敛语种. 根目录 `README.md` 是新写的, 不许动. 开工前再跑一次 `git status`, 除了 `README.md` 以外的东西和计划对不上, 就停下重新给他看一遍.

### 6. 改名与字符串替换

grep 旧项目名, 以及 lesson-smith 留下的字样. 每命中一处给 diff, 他同意再改. 要 mv 包目录之前先确认.

### 7. commit 小抄

读 `05` 第 4 节, 对着真正活下来的文件, 按最不依赖别人的先提交排一遍, README 排最后. 问过之后写进 `tmp/publish-commit-plan.md`. 把 `git add` 与 `git commit -m "..."` 的完整命令写进去, message 用第一人称过去时. 你不执行, 他自己复制. 小抄里提醒他 `tmp/` 本身不要提交.

### 8. 自查

自动转入 Audit. 只有一条 HIGH 都不剩 (或者学生明确表示接受) 时 Transform 才算完成. 完成后打印下一步: 去 GitHub 建仓库, 照 `tmp/publish-commit-plan.md` 一条条提交, 加 remote, push.

## Audit

假设读者就是在找破绽. 读 `05` 第 6 节, 每一类都对着现在这棵树跑一遍. 下面几条 README 相关的**硬检查不管 `05` 写没写都要跑**, 全部算 HIGH:

- 根目录只有一份 `README.md`, 没有 `README-<lang>.md`, 没有 `README-ORIGINAL*`.
- `README.md` 第一行不是 `---`.
- 教学词汇 (guide 第 5 节列的中英两套, 以及 `showcase-`, `TICKET`, `lesson-smith`) 在 `README.md` 和根目录其他 `*.md` 里 0 命中.
- `README.md` 里每个相对链接和本地图片都解析得到.
- 徽章指向 `.github/workflows/` 下某个 workflow 的, 那个文件存在.
- 学生选了英文, 就用 Grep 搜 `\p{Han}` 查 `README.md`, 必须 0 命中. 选了别的语种, 这一条不查.

其余类别照 `05`: 铁律删除物残留, 还留着带语种后缀的文件, commit message 里的教学口吻, git ref 暴露课程来源, 残留的子 skill 目录, 卫生问题, 可疑的雷同.

分成 HIGH MEDIUM LOW 三档, 每条写清: 找到了什么, 为什么它会露馅, 怎么修. 他挑哪条你修哪条, 同样先问再动; 涉及改写 git 历史的, 只给命令, 到此为止.

过了就直说过了. **没过就不许把条数说少.**

## Resume

从树推断停在哪一步. `tmp/publish-commit-plan.md` 在, 说明第 1 到 7 步做完了, 直接转入自查. 根 `README.md` 有内容而 `README-cn.md` 还在, 说明 README 写完了但第 5 步的执行没跑. `README.md` 还是空的或者还是一股教学味, 说明第 4 步没跑. 教学痕迹还在, 说明第 5 步没跑. 文件还带着语种后缀, 说明语种收敛没跑. 都推不出来就直接问.

## 禁止

- 不许跑任何会改动东西的 git 命令. allowed-tools 里故意没放它们. 把命令打印给学生.
- 不许没有计划确认就删东西, 铁律删除也一样.
- **不许靠后缀判断哪一版是占位符.** 打开文件看.
- **不许把旧的教学 README 改一改当新 README.** 新的从零写, 旧的删掉.
- 不许在 README 里放不存在的图片, 徽章, 命令, 链接. 不许编造数字, 结果, 特性.
- 铁律删除物还在树里时不许宣布 Transform 完成. 他拒绝删某一项, Transform 就是不能成功, 说清楚然后停下.
- 不许编他没提供过的 README 内容. 拿他的话和 repo 里读到的事实来写, 不是替他想.
- 不许建仓库, 不许 push, 不许动 commit 时间戳.
