# 完成 Vercel 基础课全部课程

## 1. 目标

把 examples 下的每个 mini task 都走完, 直到整套发布循环变成本能: 手上有一个真实跑着的网站, 装在你自己创建的 Vercel project 里; 想改就能改, 而且不惊动正在用它的人; 出了问题知道该去哪儿取证据.

这门课要验收的不是你按对了多少个按钮, 而是两件事: 关掉教程之后, 你能不能自己把改动, 发布, 观察这个循环转起来; 以及你能不能说清每一步为什么是这么设计的. 这个区分很要紧, 因为按钮会挪位置, 而背后的道理不会.

---

## 2. 要做的事情

1. 先读根目录的 README, 明白这门课该怎么学, 以及两个帮手分别在什么时候值得用.
2. 读 examples 的系列索引, 对整门课有张地图, 看清七个 mini task 是怎么分组的.
3. 按编号顺序刷完 examples 下的全部 mini task, 每个都照它自己的 TICKET 逐项确认再往下. 不要跳着做, 后面的 task 通常直接用到前面的产出.
4. 走到自测那个 task 时, 把题库从头到尾读一遍, 每题先自己答再对照, 答不上来的顺着溯源链接回去补.
5. 用 upskill-quiz 自测, 反复测到 70% 的题都能思路清晰地答出来.
6. 最后关掉教程, 凭记忆在自己的项目上完整跑一遍发布流程, 卡在哪儿就回到对应的那个 mini task 重读.

**预计用时:** 3 到 4 小时

---

## 3. 检查清单

- [ ] **全部 mini task 完成**: examples 下每个 task 的 TICKET 检查清单都已逐项打勾.
- [ ] **网站在线**: 你有一个自己创建的 Vercel project, 带一个公开可访问的 vercel.app 网址.
- [ ] **自测达标**: 用 upskill-quiz 测到 70% 的题都能思路清晰地答出来.
- [ ] **能独立复现**: 关掉教程, 你能一次走完开分支, 改动, 验证 Preview, 确认 Production 未受影响, 再合并发布.
- [ ] **能讲清概念**: 你能用自己的话说出 Deployment, Environment, branch 规则, 以及两种 Log 各自解决什么问题.
- [ ] **知道去哪儿找**: 你知道截图会过期, 界面对不上时该去查 Vercel 官方文档, 或者把截图丢给 AI.

---

## 4. 关键能力

- 从零创建 Vercel project, 用 Template 把网站部署上线, 交得出一个公开可访问的网址.
- 说得清从 GitHub 到 Vercel 这条单向链路, 以及为什么 GitHub 仓库是唯一真相来源.
- 从 production branch 开分支改代码, 让 Vercel 自动产出 Preview, 并确认 Production 纹丝不动.
- 说得出默认的 branch 到 Environment 规则, 也知道哪个 branch 算 production 是可以配置的.
- 解释 Deployment 为什么是不可变且相互隔离的, 以及 Production 这张标签为什么全项目只有一张.
- 分别打开 Build Log 与 Runtime Log, 并用 "网站打得开吗" 这一句话判断该看哪一种.
- 让自己的一次真实访问出现在 Runtime Log 里, 读出它的路径和状态码, 并知道 Hobby 计划只保留一小时.
- 把现象和日志整理成一段 AI 能直接下手的提问, 而不是丢一段原始报错就等答案.
- 诚实说出自己会什么, 还不会什么, 并在界面与教程冲突时以官方文档为准.
