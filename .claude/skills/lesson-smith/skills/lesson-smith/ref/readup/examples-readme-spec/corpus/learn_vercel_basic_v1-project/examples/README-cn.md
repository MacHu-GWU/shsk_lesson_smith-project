# Vercel 基础课系列索引

这门课教你用 Vercel 把一个网站送上线, 安全地改动它, 并在出问题时找到线索. 它刻意做得很小: 只讲平台本身, 不教前端后端怎么写. 全部读完加动手, 大约三到四个小时.

下面七篇分成四块. 第一块打底, 讲清这个平台解决的到底是什么问题, 顺便交代这份教程会过期时你该怎么办. 第二块是主线, 三篇动手, 把上线, 改动, 排错这三件事各走一遍. 第三块自测, 检验你是不是真的学懂了. 第四块收尾, 帮你定位现在的水平并选定下一步.

建议按顺序读. 后一篇经常直接用到前一篇的产出, 跳着读会缺东西.

## 1. 先搞清楚这是在解决什么问题

这一块不动手, 但它决定了你后面是在理解还是在死记.

- [01-why-vercel](01-why-vercel/README-cn.md): 一个网站上线曾经要过十几道关, Vercel 用十年把它们一层层吃掉. 读完你会明白这门课的边界在哪, 也会拿到一段应对截图过期的求助 prompt.

---

## 2. 主线: 上线, 改动, 排错

三篇连着做, 每一篇的产出都是下一篇的前提. 做完你手上会有一个真实的线上网站.

- [02-sign-up-vercel](02-sign-up-vercel/README-cn.md): 注册账号. 顺带把免费额度的边界和账户独立性这两个判断想清楚, 它们都属于错了很久才会发现的那类事.
- [03-deploy-your-first-app](03-deploy-your-first-app/README-cn.md): 用一个现成模板把网站推上线, 拿到公开网址. 重点是搞懂代码从 GitHub 到 Vercel 这条单向链路, 后面两篇都建立在它上面.
- [04-deployment-environment-and-git-branch](04-deployment-environment-and-git-branch/README-cn.md): 全课概念密度最高的一篇. 开分支改代码, 在 Preview 里验证, 确认 Production 纹丝不动, 再合并发布. 这套流程是专业团队每天在跑的东西.
- [05-view-logs](05-view-logs/README-cn.md): 出问题时去哪儿找线索. 用一句 "网站打得开吗" 分清两种日志, 再把日志整理成 AI 能直接用的提问.

---

## 3. 检验一下真的学懂了没有

- [06-prove-i-get-it](06-prove-i-get-it/README-cn.md): 三十道情景题, 都是你以后真会遇到的状况. 不考按钮位置, 只考判断和做事规范. 每题给出参考回答和深入解读, 答不上来就顺着溯源链接回去补.

---

## 4. 收尾与往前走

- [07-where-to-go-next](07-where-to-go-next/README-cn.md): 点破你带走的其实是一套和项目规模无关的做事方式, 诚实划出你还不会的部分, 说清 debug 里哪些能交给 AI 哪一样不能, 再给八个拔高方向, 每个都配好搜索关键字和可直接复制的 prompt.

---

## 5. 小结

整条线走完, 你会从 "写得出东西但别人看不到" 变成 "能把东西送上线, 能安全地改, 能在出事时不抓瞎". 这道坎在十年前拦住过无数人, 现在你可以绕过它了.

更耐用的是这门课留下的几个心智模型: 复杂度只会转移不会消失; 不可变的实例加上一个指针, 就等于安全又可逆的版本切换; 隔离空间加合并主线, 是通用的安全迭代法; 在 AI 时代, 知道去哪儿取证据比会不会分析更值钱.

最后一句请记住: 教程里的截图迟早会和你看到的界面对不上, 但底层逻辑不会变. 一切以 [Vercel 官方文档](https://vercel.com/docs) 为准, 找不到就截图问 AI.
