# Learn GitHub Basics Series Index

Eleven short lessons that take you from never having touched GitHub to running your own work on it. Everything up through lesson 08 happens in a browser, on a single repository you create in lesson 01 and keep building on. Lesson 09 moves you onto a desktop app, and the last two step back to look at the whole picture.

The arc runs from owning a place to keep your work, through the branch and merge cycle, out into permissions, tokens, and local tooling. The eight parts below are ordered by what depends on what, so working straight through is the intended path.

## 1. Foundation: A Place of Your Own, and the Confidence to Change It

Before anything else, you need somewhere that belongs to you and no hesitation about editing what is in it. Two lessons, and you have both.

- [01-create-repo](01-create-repo/README.md): Create a public repository and find out what one actually is. It holds a project, it draws the line around who collaborates, and it draws the line around who has permission. Open an incognito window to watch the internet see it, then practice getting back to it from your avatar menu.
- [02-edit-files](02-edit-files/README.md): Edit a file and commit it without leaving the browser. No installs, no setup, changes on main in about a minute.

---

## 2. The Core Loop: Branch and Merge

Branching is why Git won. You get to try something risky without putting the working version at risk, and you decide afterward whether the result was worth keeping.

- [03-working-with-git-branch](03-working-with-git-branch/README.md): Open a branch, change files on it, and watch main sit there untouched. Isolation is a lot easier to trust once you have seen it happen.
- [04-merge-branch](04-merge-branch/README.md): Open a pull request and merge your branch back into main. Commit, branch, merge, that is the loop, and you have now run all of it.

---

## 3. The Habit That Matters: Put Everything on GitHub

The rest of this course is mechanics. This part is an argument, and it is the one lesson worth more than all the others combined. Knowing the tools changes nothing if your work still lives in a folder on your desktop.

- [05-put-everything-on-github](05-put-everything-on-github/README.md): Why GitHub holds up better than Word or Google Docs for anything you intend to keep, and why a contribution graph says more about you than any line on a resume. You will move a real document over and see the difference for yourself.

---

## 4. Access Control: Who Can See, Who Can Change

Public repositories keep the early lessons simple, and simple is not how real work goes. Some things should never be visible to anyone, and some people need to get in. Visibility and access are two separate switches, and this part covers both.

- [06-create-private-repo](06-create-private-repo/README.md): Create a private repository and confirm from an incognito window that outsiders get a 404. The judgment call matters more than the click here. Learn what belongs behind that wall, and never let a secret land in a public repository.
- [07-add-collaborator](07-add-collaborator/README.md): Add a classmate or a teacher as a collaborator using their exact username. They get read and write access by default. Nobody gets in without an invitation, which is the entire point.

---

## 5. Automation: Let a Program Act for You

Anything you can click, a program can do, provided it can prove it is speaking for you. That proof is a token, and this part hands you one.

- [08-create-access-token](08-create-access-token/README.md): Generate a personal access token limited to repository scope and store it in a password manager. It behaves like a password, except it was built for machines, it gives away far less if it leaks, and you can kill it whenever you want.

---

## 6. Going Local: Work from a Desktop App

Nobody writes in a browser text box for long. Real work happens on your own machine and syncs when you are ready for it to.

- [09-use-github-desktop](09-use-github-desktop/README.md): Clone your repository with GitHub Desktop, then commit, branch, push, and merge locally with no pull request involved. Once this clicks, the browser starts to feel slow.

---

## 7. Beyond Your Own Backyard: Who Does a Repository Belong To

Nine lessons in, every repository you have touched is one you made. That ends the first time somebody hands you theirs. This part fixes the problem almost everyone hits: a coworker insists they shared a repository with you, and it is nowhere in your list.

- [10-understand-github-organization](10-understand-github-organization/README.md): Every repository hangs off an owner, and that owner is either a person or an organization. Learn to search inside an organization for the one you were given, and notice that choosing an owner is a decision you have been making all along.

---

## 8. Recap and What Comes Next

No new clicks in this part. Ten lessons worth of separate skills only become useful once you can see how they connect and can say plainly what you are able to do unaided.

- [11-recap-and-next-steps](11-recap-and-next-steps/README.md): Four segments, one line. A self-assessment table tells you where you actually stand. Two doors lead out of working alone, a job and open source, and both of them open with a pull request.

---

## 9. Summary

Eight parts, one arc. You start out with a repository you own and finish able to say who owns any repository somebody hands you. In between you pick up the branch and merge cycle, the habit of keeping your work somewhere it will last, the difference between what should be public and what should stay private, a token that lets a program work on your behalf, and a local workflow that beats clicking through a browser.

That is enough. If what you want is to use GitHub as your own main workspace, this course covers it, and GitHub stops being a programmer's tool and turns into the default place your work lives. Going further, whether that means shipping alongside coworkers or sending a fix to a project you rely on, comes down to one skill you already picked up in lesson 04. Know how to open a pull request, and that door is unlocked for whenever you decide to walk through it.
