<!--
本文件是教学 TICKET 的规范加可直接套用的模板. 这段顶部注释只服务于创作; 产出真正的 TICKET-cn.md 或 TICKET.md 时, 把整段注释删掉, 只留后面的正文.

同目录下的 corpus/ 是这一类文档的真实语料. 怎么用见本注释的 "语料" 一节.

定性: 这是任务卡片 (GitHub Project Issue). 给学生看 (主要), 也给导师或验收者看. 用途是告诉学生要做什么, 怎么做, 怎么检查和提交, 同时为验收者提供验收标准.

适用范围: 教学 Task 或 mini task 级的 TICKET, 位置标准与教学 README 一致. 在 upskill, showcase 和 readup 类型的 Repo 里, 是 examples/XY-title-here/TICKET(-lang).md; 在 evolve 类型的 Repo 里, 就在 Repo 根目录下. 四类同形, 所以这一份放在 common 下.

不在适用范围内的是 upskill, showcase, readup 三类 repo 根目录那份整门课的 TICKET: 它们各有专属 spec (readup-ticket-spec.md, upskill-ticket-spec.md, showcase-ticket-spec.md), 在本文件的三段式之上多一个 H2. 但受控词汇, H1, frontmatter, 链接这几条它们仍然继承本文件, 不要在那三份里另立一套.


== 与同目录 README 的关系 ==

TICKET (怎么验收) 和同目录 README (教什么) 是同一个 Task 的一对, 一起写也一起改. 只改一边是统稿时返工最多的来源.

正文也要对齐, 而且是逐节对齐:

第 2 节 "要做的事情" 呼应 README 的练习与操作步骤. 学生照着这一节做, 走的应该就是 README 里那条路.

第 3 节 "检查清单" 呼应 README 的学习目标. README 承诺 "学完你能 X", 这里就要有一条能当场验收 X 的.

frontmatter 的两句也是一对, 分工不同: README 那句是承诺 (学完能做到什么), TICKET 这句是判据 (做出什么才算完).


== 结构写死, 中英对照 ==

三段式, 不许增删, 不许改名. 三个 H2 按 markdown-style 从 1 连续编号, 之间用 markdown 分隔线隔开.

小节标题是受控词汇, 中英各一套, 逐字写死. 不许自由发挥成 Objective, Completion Checklist, Steps, Time estimate 之类. 理由和 README-ORIGINAL 里档位那三个词一样: 不钉死, 每次重写都会发挥出一种新说法, 同一个课程系列排进一个索引就会露馅.

  中文                   英文
  ## 1. 目标             ## 1. Goal
  ## 2. 要做的事情       ## 2. What to Do
  ## 3. 检查清单         ## 3. Checklist
  **预计用时:**          **Estimated time:**

根目录那份整门课的 TICKET 多一个第 4 节, 同样写死:

  ## 4. 关键能力         ## 4. Key Abilities

英文小节标题用 Title Case, 其中的介词与不定式的 to 保持小写, 所以是 What to Do 而不是 What To Do.


== H1 ==

规则与教学 README 相同: 只用字母, 数字, 文字, 逗号, 冒号, 句号. 禁 emoji, 引号, 双引号, 方括号, 以及三种破折号 (em dash, en dash, ASCII hyphen). 这一条由 lint 的 h1 检查卡死.

英文版最容易在这里翻车的是带连字符的术语: from-scratch mode, mini-project-design 这类词在正文里合法, 写进 H1 就报错. 改成不带连字符的写法 (from Scratch), 或者换一个词, 不要把连字符换成任何一种破折号, 那三种全在禁用集里.

额外一条: 标题里不许出现 repo 名字作为通用前缀. 凡是能用程序批量生成的一律不手写, repo 前缀这类交给程序.


== frontmatter, description ==

这个 Task 的 "完成判据": 一句话说清做出什么, 或能当场演示什么, 才算完成 (Definition of Done 压成一句). 它出现在看板与 Issue 列表里, 面向判断 "这活儿是啥, 达没达标" 的人.

它和同目录 README 那句是同一个 Task 的两张脸: README 句说学完能做到什么 (承诺), 这句说做出什么才算完 (判据). 纯知识型 Task 就写成可当场检验的理解 (你能解释清楚 X).

形态四条, lint 全都卡:

  值必须用双引号包起来, 形如 description 冒号空格再双引号
  值保持一行, 不含换行
  值里不许出现任何引号类字符: 双引号, 单引号 (ASCII 撇号也算), 反引号, 以及四个弯引号
  长度上限中文 400 字符, 英文 800 字符 (不含包裹的双引号)

紧度按海拔走: 这是 Task 级的 description, 一句话, 说完就停. 别拿 README-ORIGINAL 那种用足预算的写法套过来. 英文那一档翻倍是为了让重写不必压缩, 不是让你多写一句.

其余细节见 repo-layout.md 第 4 节.


== 链接约定 ==

TICKET 正文最终会被程序放进 GitHub Issue, 所以对链接有讲究.

禁止指向 repo 内文件或目录的相对路径链接 (形如指向 ../ 或 ./ 某个文件的 markdown 链接). 相对路径在 GitHub Issue 里是死的, 点不动. 要指向 repo 里某个文件, 目录或 mini task 时, 用文字提及 (直接说文件名或位置), 不写成链接.

允许绝对 URL: 形如 https://domain/href 的绝对链接完全可以照常用.

不手写指向本教程或本 Issue 自身的 GitHub 链接: 生成 Issue 时程序会确定性地拼出来, 不手写.

反过来还有一条, 给重写英文版那一步的: 不许给 TICKET 新添相对路径链接, 哪怕正文里提到了某个 mini task, 看起来该链一下.


== 三节各写什么 ==

第 1 节 目标: 1 到 3 段. 说清这个 Task 要完成什么, 以及为什么值得做. 不复述 README 的教学内容, 只交代这一趟的落点. 如果这个 Task 有一条学生最容易忽略的红线 (例如 "读完不算完, 得真交出一份东西"), 在这里点破, 别留到检查清单才第一次出现.

第 2 节 要做的事情: 有序列表, 每条一个可执行动作, 动词开头, 具体到学生知道手往哪儿放. "理解 X" 不是动作, "合上教程用自己的话讲一遍 X, 再回去对照哪里偏了" 才是. 顺序就是学生实际操作的顺序. 末尾单起一行给预计用时, 用受控词汇那一行的写法; 阅读量和动手量差得远时, 可以在括号里补一个只读不做的估计.

第 3 节 检查清单: markdown todo 列表, 每条一个 checkbox, 形如粗体标签加冒号加一句完成标准.

  cn 形如   - [ ] **标签**: 完成标准的简述.
  en 形如   - [ ] **Label**: the completion bar, in one sentence.

英文里冒号后面用小写起句, 句末照常给句号. 这是 Chicago 的写法 (冒号后只跟一个完整句子时不大写), 也让粗体标签和后半句读起来是连着的一句话.

条目要能被第三方当场判定真假. 理解型的写成 "你能说清 X" 或 "你能举出 X", 产出型的写成 "X 已经存在于哪里, 长什么样". 常见区间是 5 到 9 条; 少于 5 条通常是 README 的学习目标没被逐条接住, 多于 9 条通常是把 "要做的事情" 又抄了一遍.


== 英文版专属 ==

英文版不是翻译, 是重写, 随整门课那一次统一重写产生 (见 rewrite-en-spec.md). 下面几条只对英文版生效.

frontmatter 里一个撇号都不要用. 规则文本上 "值内不含引号类字符" 本意指成对的引号, 但 lint 实际检查的字符集里包含 ASCII 撇号, 所以 you've, doesn't, it's 写进 description 会当场报错. 缩写在这里写全就是了, 所有格换成 of 结构或者换个说法; 这两句是要被复制粘贴进看板的一行, 语域比正文正式一点反而合适.

正文里则允许并鼓励 contraction (you'll, isn't, don't). TICKET 是对着学生说的话, 不是验收单据的法务文本.

第 2 节那些祈使句要写成人话. 中文 "通读本节 README" 逐词译过去是 read this section README through, 英文里该是 read this lesson README start to finish. 这类逐词直译的 calque 是 TICKET 最常见的翻译腔, 因为这一节全是短祈使句, 每句都短到看不出别扭, 连起来读才发现不像英文.

一条判据: 写完之后当成英文读一遍, 不要当成译文读. 读着卡住的地方就是翻译腔.


== 语料 ==

corpus/ 下是真实 repo 的 TICKET, 尽量成对给出中英两版. 它们是例子, 不是标准答案, 也不是判据. 上面这份规范才是权威; 语料和规范对不上时以规范为准 (语料里有存量文件写于规范定稿之前, 小节标题或撇号可能不合现在这一版).

动笔前不要把 corpus 下的都读一遍, 那是往上下文里灌噪音. 挑一到两份和你手上这个 Task 最接近的读一遍就够了, 要找的是分寸: 一条 "要做的事情" 具体到什么程度就够了, 一条检查项怎么写才判定得了真假, 英文版读起来为什么不像译文. 找的不是句式模板, 别照着抄结构.
