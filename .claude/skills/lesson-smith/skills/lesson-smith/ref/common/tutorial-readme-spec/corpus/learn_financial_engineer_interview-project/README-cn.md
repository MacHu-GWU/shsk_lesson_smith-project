# 用 AI Agent 刷 Quant 面试题: 从测出盲区到能讲清楚

> 这一节不教你背 264 道题的标准答案, 而是教你用 AI Agent 把自己的知识盲区测出来, 再一块一块补上.

## 1. 概览

金融工程 (Financial Engineering), 业内更常叫 Quant, 坐在 finance, mathematics 和 technology 的交叉口. 这个岗位的面试有个特点: 它几乎不问定义. 面试官不会让你背 Black-Scholes 公式, 而是丢给你一个具体场景, 看你怎么拆.

这就带来一个尴尬的处境. 你可以把教科书从头读到尾, 每一章都觉得看懂了, 然后在面试里被一个追问打回原形. 因为 "看懂" 和 "讲得出来" 之间隔着一条鸿沟, 而只有被人当面追问的时候, 这条鸿沟才会暴露.

这个题库有 264 道题, 分 E, M, H 三档难度, 覆盖 23 个主题, 从衍生品定价一路到低延迟计算. 但这一节要教你的不是刷完它, 而是用它做一件更划算的事: 用 AI Agent 当陪练, 花两三个小时先把自己的盲区测出来, 再定向补. 测出来的盲区比读完的章节值钱得多.

---

## 2. 学习目标

先说清楚为什么值得这么练.

大多数人准备 Quant 面试的方式是线性的: 找一本书, 从第一章读到最后一章, 读完觉得心里有底了. 问题是这条路径完全不考虑你已经会什么. 你在自己熟悉的领域反复投入时间, 而真正会让你挂掉的那几个主题, 恰恰是你不知道自己不知道的.

AI Agent 改变的正是这一点. 它能随机出题, 逼你走出舒适区; 能当场追问, 让你在自己家里就经历一遍面试现场的压力; 还能在你答不上来的时候立刻切换成讲解, 把这个洞当场补掉. 这是一本书做不到的.

学完这个 Task, 你将能够:

1. 用 `/practice-cn` 在面试模式和学习模式之间自如切换, 知道什么时候该测, 什么时候该补.
2. 读懂一次基线测试的反馈, 从中点出自己 1 到 3 个具体的薄弱主题, 而不是笼统地说 "数学不行".
3. 用学习模式把一个薄弱主题深挖到能用自己的话讲出来, 并用隔天复测验证这个进步是真的.
4. 说清一个模型凭什么成立, 它的假设在什么条件下会断, 断了之后换什么工具.
5. 给自己排出一份下一步练什么的计划, 具体到主题和难度.

## 4. 你将学到什么

这一节不产出代码, 它产出两样东西.

第一样是一张你自己的知识盲区地图: 23 个主题里, 哪几块是你真的会, 哪几块是你以为自己会, 哪几块是你根本没碰过. 这张图是测出来的, 不是猜出来的.

## 5. 先分清你要面的是哪一种 Quant

Quant 不是一个岗位, 是一族岗位. 它们的面试侧重差得很远, 你得先知道自己要面的是哪一种, 才知道该在哪一档难度上花时间.

| 角色 | 核心职责 | 典型工作内容 |
| :--- | :--- | :--- |
| Quant / 金融工程师 | 构建定价模型, 风险系统, 交易策略 | 衍生品定价, 风险建模, Alpha 研究, 回测 |
| Quant Developer | 在生产环境里实现量化模型 | C++ 与 Python 定价库, 交易系统, 数据管道 |
| Quant Researcher | 发现新的交易信号和策略 | 统计分析, 回测, Alpha 生成 |
| Risk Quant | 构建和验证风险模型 | VaR, 压力测试, 模型验证, 监管合规 |
| Quant Trader | 用量化方法执行交易 | 做市, 统计套利, 执行算法 |

这个题库覆盖的是这几种角色的公共底盘: 每个 Quant 都得掌握的那部分. 所以不管你面哪一种, 这里的题都不白做; 但真到了针对性准备的阶段, 你还需要按目标公司和资产类别再补一层, 这个题库不替你做那件事.

## 6. Quant 面试真正考的是判断力

看几道这个题库里的真实问题:

- Black-Scholes 不适用的时候, 你怎么给一个奇异期权定价?
- VaR 模型的突破次数明显超标了, 问题出在哪?
- 怎么在不引入前视偏差 (look-ahead bias) 的前提下回测一个策略?
- 历史模拟 VaR 和参数 VaR 的区别在哪, 什么时候该用哪个?
- 利率变成负的之后, 你的模型要改什么?

注意这几道题的共同点: 没有一道能靠背公式回答. 它们问的都是 "在这个具体情况下, 你怎么判断". 这就是 Quant 面试的形状.

由此可以推出一条贯穿全节的判据. 判断你学没学会一个概念, 标准不是你能不能复述定义, 而是这两条:

- 你能不能用自己的话把它讲给一个不懂的人听.
- 你知不知道它在什么条件下会失灵.

第二条尤其重要, 而且几乎是区分初级和资深的分水岭. 每个模型都是一组假设的产物, 假设成立它就好用, 假设断了它就给你一个精确的错误答案. 面试官追问两句, 问的往往就是这个边界.

## 7. 题库的地形: 三档难度, 23 个主题, 264 道题

动手之前先看地图. 三档难度问的不是同一类问题:

| 档位 | 题数 | 问什么 | 典型形态 |
| :--- | :--- | :--- | :--- |
| E (简单) | 约 92 | 是什么, 为什么重要 | 核心概念, 术语, 基本机制 |
| M (中等) | 约 88 | 怎么构建 | 实现细节, 生产环境里的模式 |
| H (困难) | 约 84 | 为什么这么选, 怎么权衡 | 架构设计, 高级理论, 取舍分析 |

23 个主题在三档里是同一套, 编号也对齐, 所以 `E-07` 和 `H-07` 讲的是同一个主题的两个深度. 主题覆盖衍生品, 固定收益, 市场微观结构, 结构化产品, 监管框架, 概率统计, 随机微积分, 数值方法, 优化理论, 时间序列, Python, C++, 系统设计, 低延迟计算, 数据工程, 云计算, 机器学习, 另类数据, 组合构建, 风险建模, 回测方法, 模型验证, 以及跨领域的问题排查.

每道题有一个唯一 ID, 格式是 `{档位}-{主题}-{序号}`:

- `E-01-01` 是简单档, 主题 01, 第 1 题.
- `M-04-02` 是中等档, 主题 04, 第 2 题.
- `H-07-03` 是困难档, 主题 07, 第 3 题.

这个 ID 是你和 Agent 之间的通用语: 想练哪道直接报 ID 就行.

两份索引文件的分工也要知道: `questions.md` 是完整大纲, 264 道题每道都有详细描述, 适合泛读找感觉; `questions-index.md` 是速查表, 只有 ID 和标题, 按难度和主题组织, 适合定位.

按背景选起点难度, 别从头刷:

| 你的背景 | 建议起点 |
| :--- | :--- |
| 刚接触量化金融 | 从 E 开始, 先把地基打实 |
| 有 1 到 2 年经验 | E 快速过一遍, 重点刷 M |
| 有 3 年以上经验 | 直接上 M 和 H |
| 有明确目标岗位 | 按目标职级选对应难度 |

拿不准就把简历或项目经历粘给 Agent, 让它替你判断:

```
这是我的背景: [粘贴简历或项目经历]
请推荐适合我的题目难度和主题.
```

## 8. 一道题长什么样

每道题都是一份独立的讲解文档, 落在这样一个路径下:

```
pool/{档位}/{主题}/{题目ID}/README.md
```

例如:

```
pool/01-easy/01-derivatives-fundamentals/E-01-01-forward-vs-futures/README.md
pool/02-medium/07-stochastic-calculus/M-07-01-black-scholes-pde/README.md
pool/03-hard/13-system-design/H-13-01-distributed-risk-platform/README.md
```

一份题解的骨架是固定的, 认识这个骨架你才知道该重点看哪一段:

| 小节 | 它给你什么 |
| :--- | :--- |
| Interview Question | 面试官原话形态的问题, 先自己答一遍再往下看 |
| Question Breakdown | 这道题在考什么, 面试官想听到哪几个点 |
| Key Concepts | 回答需要的概念铺垫, 逐个讲清 |
| Reference Answer | 一份合格答案长什么样, 结构和深度都是参考 |
| Follow-Up Questions | 追问, 这里才是拉开差距的地方 |
| Real-World Use Cases | 真实市场里这个概念在哪儿咬过人 |
| Recommended Reading | 想再深挖时去哪儿 |

用法上有个小建议: 看到 Interview Question 就停住, 先自己组织一遍答案, 再往下对照 Reference Answer. 直接顺着读下来什么都懂, 那是阅读的错觉, 不是掌握.

## 9. 两种模式: 面试模式测, 学习模式补

在 Claude Code 里敲:

```
/practice-cn
```

Agent 先问你怎么选题, 三个选项:

1. 自己选题, 你报一个题目 ID.
2. 随机出题, 从整个题库里随机抽一道.
3. 按主题随机, 你指定主题或难度, 它在这个范围里随机抽.

选完题, 它再问你用哪种模式. 这两种模式的分工是这一节的核心:

| | 面试模式 | 学习模式 |
| :--- | :--- | :--- |
| 它干什么 | 出 3 道选择题加 3 道简答题考你 | 带你读题解, 你随时提问 |
| 节奏 | 逐题呈现, 答完一题给一题反馈 | 你控制, 想追问几轮都行 |
| 产出 | 一份得分和薄弱点清单 | 一个你能讲出来的概念 |
| 什么时候用 | 你想知道自己到底会不会 | 你已经知道自己不会 |
| 它逼你做的事 | 开口把答案说出来 | 追问到没有模糊地带为止 |

简答题是面试模式的重头戏. 选择题能靠排除法蒙对, 简答题不行, 它要求你用自己的话解释, 而 Agent 会针对你回答里的漏洞给具体反馈. 这个环节最接近真实面试的感觉, 也最容易让人发现 "原来我讲不清楚".

学习模式则不要客气. 它不会因为你问了第五个追问就不耐烦, 而这正是 AI 相对于人类导师的优势. 一个概念你觉得还有半点含糊, 就继续问, 直到你能反过来把它讲给别人听.

## 10. 三条容易被跳过的纪律

方法本身不难, 难在这三条上, 而它们恰好都是最容易被跳过的.

**第一条: 基线那一轮必须随机出题.**

自己挑题的时候, 人一定会挑软柿子捏. 你会不自觉地选一个自己有印象的主题, 答得挺顺, 然后得出一个虚高的结论. 随机出题是唯一能防住这件事的机制. 基线的意义就是诚实, 不诚实的基线不如没有.

**第二条: 复测必须隔天.**

当天学完当天测, 测的是短期记忆, 分数高得毫无意义. 隔至少一天再测同一个主题, 测的才是有没有真正沉淀下来. 这就是 spaced repetition, 间隔本身是方法的一部分, 不是为了拖时间.

**第三条: 判据是讲得出来, 不是看得懂.**

读题解的时候一切都很顺, 这是最危险的状态. 合上文档用自己的话复述一遍, 你才知道刚才那种流畅有多少是文档给的. 每次深挖结束前, 强迫自己做一次不看笔记的口头复述.

这三条串起来就是这一节的完整方法: 随机测出基线, 定向补一个主题, 隔天复测验证, 然后换下一块.

## 11. 不用 Agent 的自主阅读路线

没有 Claude Code 环境也能用这个题库, 只是要自己做 Agent 替你做的那部分.

1. 从 `questions-index.md` 挑一道题, 记下它的 ID.
2. 按第 8 节的路径格式找到那道题的 README, 或者用仓库里的 `locate_question.py` 定位.
3. 读到 Interview Question 就停下, 自己写一份答案, 再往下对照.
4. 把 Follow-Up Questions 也自己答一遍, 差距通常就藏在这里.

题库本身是普通的 Markdown, 所以你也可以把某一份题解整个贴给任何一个 AI, 让它扮演面试官考你. 手动做这件事比 `/practice-cn` 麻烦, 但方法是同一套: 先测, 再补, 隔天验.

## 12. 练习

四个练习是连着的一条路径, 中间有一次必须隔夜, 所以整体跨 3 到 5 天.

### 练习 1: 用随机测试打一个诚实的基线

**目标:** 拿到一份没有被自己美化过的起点数据.

**怎么做:**

1. 花 10 分钟翻一遍 `questions-index.md`, 对三档难度和 23 个主题有个大致印象.
2. 按第 7 节的表格定下自己的起点难度. 拿不准就把简历粘给 Agent 让它推荐.
3. 敲 `/practice-cn`, 选随机出题.
4. 选面试模式.
5. 把 3 道选择题和 3 道简答题全部答完, 中途不要去查资料.
6. 把这一轮的得分和反馈原样存下来, 这是你的基线.

**你会观察到:**

选择题的分数多半比简答题好看. 这个差距本身就是信息: 它说明你对概念有认识, 但还没到能组织语言讲出来的程度.

> **关键洞见:** 基线的价值不在分数高低, 在于它是随机抽出来的. 只有随机, 后面所有的对比才有意义.

### 练习 2: 深挖一个薄弱主题

**目标:** 把地图上最暗的一块补到能开口讲.

**怎么做:**

1. 对着练习 1 的反馈, 把答错和只答对一半的题归到主题上.
2. 挑出得分不到一半的 1 到 3 个主题, 按对目标岗位的重要性排个序.
3. 敲 `/practice-cn`, 选按主题随机, 指定排第一的那个主题.
4. 切到学习模式, 跟着 Agent 读这份题解.
5. 每读到一个模糊的地方就追问, 别放过. 至少问到 Follow-Up Questions 那一层.
6. 合上对话, 不看任何东西, 用自己的话把这个概念口头讲一遍.

**你会观察到:**

第 6 步会比你预期的难. 讲到一半卡住的地方, 就是你还没真正拿下的地方, 回去接着问.

> **关键洞见:** 追问的成本在 AI 这里几乎是零. 你在真人面前会不好意思问第五遍, 在这里不会, 这是你该用尽的优势.

### 练习 3: 隔天复测, 验证进步是真的

**目标:** 用一次对照实验确认深挖有效, 而不是自我感觉良好.

**怎么做:**

1. 至少隔一天. 不要当天做完练习 2 就接着测.
2. 敲 `/practice-cn`, 选按主题随机, 指定和练习 2 同一个主题.
3. 选面试模式, 完整答完 6 道题.
4. 把新分数和基线放在一起比, 重点看简答题那部分的反馈变化.
5. 再挑 2 到 3 个还没碰过的主题各跑一轮, E, M, H 三档都要碰到, 别只在舒服的那一档里打转.

**你会观察到:**

如果深挖到位了, 简答题的反馈会从 "需要改进" 挪到 "部分正确" 或 "正确", 而且 Agent 指出的问题会从 "概念不清" 变成 "表述可以更精确". 这个变化比分数本身更能说明问题.

> **关键洞见:** 隔夜这一步不是仪式. 当天测和隔天测量的是两个不同的东西, 只有后者能预测你在面试当天的表现.

### 练习 4: 把一个概念用 Python 写出来

**目标:** 让一个你刚学明白的概念从纸面落到会跑的代码上.

**怎么做:**

1. 从你深挖过的主题里挑一个可实现的概念, Monte Carlo 期权定价或者历史模拟 VaR 都合适.
2. 用 Python 从头实现一遍, 不要直接调现成的库函数.
3. 喂给它一段真实的市场数据跑一次.
4. 故意破坏一个假设再跑一次: 比如把波动率换成随时间变化的, 或者把收益分布换成厚尾的.
5. 记下结果在哪一步开始变得不可信.

**你会观察到:**

第 4 步是重点. 模型在假设成立时给出的漂亮结果, 和假设断掉之后给出的同样漂亮但完全错误的结果, 长得一模一样. 亲眼看过一次, 你对 "模型失效边界" 的理解就不再是一句话了.

> **关键洞见:** 面试官问 "这个模型什么时候会失灵" 的时候, 亲手让它失灵过的人和只在书上读过这句话的人, 答案的质地完全不同.

## 13. 回顾: 我们学到了什么

- Quant 面试考的是具体场景下的判断力, 不是定义和公式的复述能力.
- 学没学会的判据有两条: 你能用自己的话讲出来, 你知道它什么时候会失灵.
- 264 道题不是用来刷完的, 是用来测出盲区的. 测出来的盲区比读完的章节值钱.
- 面试模式负责暴露问题, 学习模式负责解决问题, 两者要交替用, 不是二选一.
- 基线必须随机出题, 否则你会挑软柿子, 得到一张假地图.
- 复测必须隔天, 当天连测量的只是短期记忆.
- 亲手实现一遍并看着它翻车, 是把 "知道" 变成 "懂" 的最短路径.

从 "我读完了一本量化金融的书" 到 "我知道自己有哪三个洞并且补掉了两个", 这个转变才是面试当天真正帮到你的东西.

## 14. 导师寄语

**为什么这个练习重要:**

我见过很多准备 Quant 面试的人, 时间投入都不少, 结果差别却很大. 差别几乎不在于读了多少, 而在于有没有在准备阶段就把自己暴露出来.

一个人如果只是读, 他会一直待在 "我大概知道" 这个舒服的状态里, 直到面试当天被追问三轮才发现地基是空的. 而那时候没有第二次机会. AI Agent 最大的价值就是把这个暴露的时刻提前到你家里的沙发上, 代价只是一点尴尬.

**关键洞见:**

- 理解推导比记住公式重要. 知道 Black-Scholes PDE 为什么成立, 比会往里面代数字值钱得多, 因为面试官的追问总是往推导的方向走.
- 权衡思维比找银弹重要. 每个模型都有失效的边界条件, 资深和初级的分水岭往往就在你知不知道自己的工具什么时候会失灵.
- 动手实现比纯看理论重要. 这个题库只是起点, 真正的学习发生在你用 Python 或 C++ 把模型写出来, 然后看着它在真实数据上翻车的时候.
- 量化金融这个领域大到没有人能掌握一切. 承认这一点, 然后把有限的时间花在测出来的洞上, 而不是平均分配.

**下一步:**

把这一节的四步循环变成你接下来几周的默认节奏: 随机测一轮, 挑一个洞深挖, 隔天复测, 换下一个洞. 每轮 20 到 30 分钟, 一周三四次就够. 几周下来, 你手上会有一张越来越亮的地图, 而不是一堆读过的章节.

真到了针对性准备阶段, 再按目标公司的方向补一层: 买方和卖方问的东西不一样, 不同资产类别的深度也不一样. 这个题库给你的是那个公共底盘, 底盘扎实了, 补那一层很快.

## 15. 速查

**开始练习:**

```
/practice-cn
```

**选题的三种方式:** 自己选题报 ID, 随机出题, 按主题随机.

**两种模式:** 面试模式 (3 道选择题加 3 道简答题, 有反馈和得分), 学习模式 (自己的节奏, 随时追问).

**题目 ID 格式:** `E-XX-XX` 简单, `M-XX-XX` 中等, `H-XX-XX` 困难.

**题解路径:**

```
pool/{档位}/{主题}/{题目ID}/README.md
```

**关键文件:**

- `questions.md`: 完整大纲, 264 道题的详细描述.
- `questions-index.md`: 速查索引, 按难度和主题组织.
- `locate_question.py`: 按题目 ID 定位题解路径.
- `pool/`: 所有题解的根目录.

**一轮标准练习:** 20 到 30 分钟, 3 道选择题加 3 道简答题, 做完看反馈, 记下薄弱主题, 隔几天再来一轮.
