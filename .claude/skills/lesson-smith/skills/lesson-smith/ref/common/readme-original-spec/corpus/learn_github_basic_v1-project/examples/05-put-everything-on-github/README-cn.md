# 把所有事情都放到 GitHub 上

> 这一节不写代码, 而是完成一次观念转变: 从今天起, 把你做的所有事情都放到 GitHub 上管理.

## 1. 概览

恭喜你走到了这门课的最后一节. 前面四节你学会了四件具体的事: 创建 repo, 在网页端编辑文件, 使用 branch, merge branch. 这些都是实打实的技能.

这一节给你的东西不一样. 它不再往你的技能表里加东西, 而是改你的默认动作.

这个转变一句话就能说完: **从今天起, 把你做的所有事情都放到 GitHub 上**. 不只是代码, 还有笔记, 作业, 文档, 以及 AI 生成的草稿, 全部放上去.

这不是程序员的专利. 它关乎一件对所有人都成立的事: 在 AI 时代, 如何为自己留下一份永久的, 可验证的, 任何人都无法造假的记录.

---

## 2. 学习目标

先说清楚这件事为什么值得你认真对待.

在 AI 时代, 一个人自己贴的标签越来越不值钱. 简历可以注水, 作品集可以编造, AI 还能替你生成一大堆听起来很厉害, 但你其实没做过的东西.

那么怎么证明你真有本事? 答案是**时间**. 一份日复一日, 周复一周, 月复一月积累起来的记录, 谁都伪造不来. 而 GitHub 是唯一能让这种长期记录变得毫不费力的平台. 这就是为什么这个习惯值得现在就建立, 而不是等以后.

学完这个 Task, 你将能够:

1. 说清楚为什么 GitHub 比 Word 和 Google Docs 更适合管理文档.
2. 读懂 GitHub contribution graph (贡献图), 知道它在职业发展上意味着什么.
3. 解释为什么 GitHub 加 AI 从根本上强于任何单个软件内置的 AI 助手.
4. 定下把日常工作迁到 GitHub 的具体计划, 并开始执行.

## 5. Word 和 Google Docs 的问题

先看今天大多数人是怎么管理文档的.

你用 Word 写一份文档, 改了十遍, 发邮件给同事, 同事又改, 然后所有人都搞不清哪个才是最新版. Google Docs 好一些, 多人可以同时编辑. 但你每改一次, 旧的那一版实际上就 "消失" 了. 它确实存了版本历史, 只是没人会去翻. 你的工作记录被藏了起来, 没有结构, 困在一个 app 里出不来.

GitHub 的做法完全不同. 每一次修改都是一个 **commit**, 一条永久的, 带时间戳的记录. 什么变了, 什么时候变的, 为什么变的, 全都摆在明面上.

把三者放在一起对比:

| 维度 | Word | Google Docs | GitHub |
| :--- | :--- | :--- | :--- |
| 每次修改 | 覆盖原文件, 或另存成新文件名 | 覆盖当前版本 | 生成一个 commit, 永久保留 |
| 历史记录 | 靠文件名手工维护 | 有, 但埋在菜单深处 | 一等公民, 随时可查 |
| 改动可见性 | 看不出哪里变了 | 要逐条翻版本 | 逐行 diff, 一目了然 |
| 记录的归属 | 文件在谁手上就算谁的 | 绑在一个账号和一个 app 里 | 公开可验证, 随时可迁出 |
| 谁能看到 | 收到那封邮件的人 | 被分享到的人 | 你自己决定公开还是私有 |

信息的本质就是文本. Word 用专有格式包装文本, Google Docs 用网页应用包装文本. GitHub 则以最纯粹的方式管理文本, 再给它加上版本控制, 协作工具, 和一条永久的审计追踪 (audit trail). 回到最本质的东西, 往往才最强大.

## 6. 为什么 GitHub 加 AI 强大得多

Google Docs 里内置了 Gemini. 它能总结文档, 建议修改, 回答问题. 听起来不错, 但它有一个根本局限: **Gemini 只知道它正在看的那一个文档**.

它不知道你其他的文件, 不知道你的项目历史, 不知道你的代码库, 不知道你的笔记, 也不知道你之前做过哪些决策. 每开一次口, 你都得从头把背景讲一遍.

在 GitHub 上, AI 能拿到的东西完全不是一个量级:

| 对比项 | 文档内嵌的 AI | 能看到整个 repo 的 AI |
| :--- | :--- | :--- |
| 可见范围 | 当前打开的这一个文档 | 所有文件, 所有分支 |
| 历史 | 看不到 | 读得到每一条 commit message, 看得出你的思路怎么演进 |
| 自动化 | 基本没有 | 可以写脚本, 可以批量处理 |
| 代表工具 | Google Docs 里的 Gemini | GitHub Copilot, Claude Code |

打个比方. 一个只能看一个文档的 AI, 像一位每天早上都会失忆的顾问, 你得反复交代背景. 一个能看到整个 repo 的 AI, 像一位从第一天起就跟你一起工作的团队成员, 它知道来龙去脉. 这个差距是数量级上的.

## 7. 一片绿, 你最好的简历

先把这个东西定义清楚. 打开任何一个 GitHub 用户的主页, 你会看到一片由绿色小方块组成的网格: 一年里每天一格, 每格代表那天的贡献 (commit, pull request, code review 等等), 贡献越多, 绿色越深. 这就是 **contribution graph** (贡献图), 大家习惯叫它 "一片绿".

这张图在不同人身上差别极大:

| 谁 | 贡献图长什么样 | 它说明了什么 |
| :--- | :--- | :--- |
| 刚入门的学生 | 大片灰色, 零星几个绿点 | 刚开始动手 |
| 在职工程师 | 有一些绿色, 忙时密集, 闲时稀疏 | 在做事, 但还没形成节奏 |
| 资深工程师或活跃开源贡献者 | 满屏深绿, 几乎每天都有 | 每天都在构建, 审查, 改进 |

当招聘经理打开你的主页, 这张图讲的故事是任何简历都比不了的: 这个人每天都在做事, 不是嘴上说说, 而是真的在持续构建.

下面是一位活跃开发者连续五年的贡献图. 你能直观感受到什么叫 "满屏深绿": 每一年都密密麻麻, 一年下来几千次贡献, 而且一年接一年从未间断. 这种日积月累, 谁都伪造不来的记录, 就是最有说服力的简历.

我们来算一笔账, 你就明白几百上千次贡献到底意味着什么.

一年有 365 天, 但真正干活的工作日大概只有 200 天. 只要你在工作日保持一个正常节奏, 每天至少提交一次 (有些天在开会, 有些天没怎么动手, 但也有些天一口气提交十几次), 一周下来轻轻松松就有十来个贡献. 52 周累积起来, 一年几百个是最起码的.

所以反过来想. 如果一个人的贡献图一年连几百个都凑不齐, 说明什么? 说明他平时基本没在动手, 没在学习, 也没在提升自己. 这个世界上最新最厉害的东西几乎都活在 GitHub 上, 你不在上面留下痕迹, 多半就是你根本没去碰它们. 贡献图不会撒谎, 它诚实地记录了你到底有没有在持续投入.

这里还有一个关键点: **每个绿色方块都能点开**. 点进去就能看到那个人那天到底 commit 了什么, 每一个改动, 每一个文件, 每一行代码都清清楚楚. 这就是为什么造假行不通. 一墙绿色, 点开却发现每个 commit 只是加了个空格, 一眼就穿帮. 那叫造假, 不叫贡献历史.

## 8. 正确地积累你的一片绿

一片绿不是靠刷出来的. 把不该做的和该做的放在一起看, 界线很清楚:

| 不要做 | 应该做 |
| :--- | :--- |
| 为了让方块变绿而做无意义的 commit | 把上课笔记放到 GitHub, 每次学习就是一个 commit |
| 反复编辑同一个文件, 做无关痛痒的改动 | 把作业和文档放到 GitHub, 每次修改都被追踪 |
| 用脚本或机器人自动提交空改动 | 把 AI 生成的文档放到 GitHub, 草稿, 修改, 最终版都留下 |
| 盯着连续天数刷, 而不管有没有真实产出 | 把项目代码放到 GitHub, 关键是坚持 |

左边那一列一眼就能被看穿. 点开方块, commit 细节明明白白摆在那里. 如果全是 fix typo 接着 fix typo again, 会被直接判定为造假, 这比没有记录还要糟糕.

核心在于, 你并不需要做额外的工作. 你本来就在学习, 在写东西, 在做项目, 只不过换一个地方做: 在 GitHub 上做, 而不是在 Word 里做. 绿色方块是这件事的副产品, 顺其自然就有, 不用刻意.

## 9. GitHub 不是理科生的专利

有一个常见误解, 认为只有程序员才用 GitHub. 这个观念已经过时了.

GitHub 本质上是一个**带版本控制的文本管理系统**. 任何能用文字表达的东西都可以放上去:

- 会议纪要和议程.
- 研究报告和论文.
- 项目计划和任务清单.
- 学习笔记和学习日志.
- 团队协作文档.
- 数据分析笔记本, Jupyter Notebook 在 GitHub 上显示得特别好.

律师可以记案件笔记, 市场经理可以管理活动方案的多个版本, 学生可以整理课程作业. 领域千差万别, 但受益的原则是同一套: 版本控制, 透明度, 永久性. 在 AI 时代, 这是管理信息, 留下记录最高效的方式, 不管你在哪个专业领域.

## 10. 练习

### 练习 1: 探索你的贡献图

**目标:** 看清一张真实的 contribution graph 长什么样, 以及它能揭示什么.

**怎么做:**

1. 打开你自己的 GitHub 主页, 点右上角头像, 选 Your profile.
2. 往下滚动, 找到 contribution graph.
3. 数一数到目前为止你有多少个绿色方块. 做了这么多节课的练习, 应该已经有一些了.
4. 点开其中一个绿色方块, 看看那天你 commit 了什么.
5. 去看一位经验丰富的开发者或活跃开源贡献者的公开主页.
6. 对比两张图, 注意密度和持续性上的差异.

**你会观察到:**

你的图上有一些来自这门课练习的绿点, 而对方绿得多得多. 这个差距不是天赋, 是习惯.

> **关键洞见:** 你在这门课里做的每一个 commit 都已经出现在贡献图上了. 你已经在积累记录了, 只需要继续下去.

### 练习 2: 把一个文档搬到 GitHub 上

**目标:** 亲手把一个非代码文档放到 GitHub 上管理.

**怎么做:**

1. 想一个你最近在 Word 或 Google Docs 里写的文档, 上课笔记, 作业, 随便什么都行.
2. 打开你自己的 repo.
3. 创建一个新文件, 起一个有意义的名字, 比如 `notes/2026-04-13-class-notes.md`.
4. 把 Word 或 Google Doc 的内容复制进去. 能用 Markdown 格式化更好, 纯文本也完全可以.
5. 写一句有意义的 commit message, 比如 `Add class notes from April 13 lecture`.
6. 提交这个文件.

**你会观察到:**

这份文档现在有了一个永久的家, 而且被版本控制了. 明天再编辑, 历史会被完整保留, 你的贡献图上又多一个绿点.

> **关键洞见:** 整个过程不到两分钟, 却创造了一份永久的, 可验证的工作记录. 这就是把 GitHub 作为默认工作环境的力量.

---

## 11. 回顾: 我们学到了什么

- Word 和 Google Docs 用起来方便, 但不留下持久的, 结构化的记录.
- GitHub 把每一次编辑都变成永久的, 带时间戳的, 可验证的贡献记录.
- 贡献图是你坚持的视觉证明, 而且点得开, 查得实, 所以伪造不了.
- GitHub 加 AI 从根本上强于单文档 AI, 因为它拿得到完整的项目上下文.
- 你不需要额外的努力, 只是换个地方去做你本来就在做的事.
- GitHub 不只是写代码用的, 它是 AI 时代管理一切文本信息的最佳工具.

从 "我用 GitHub 交代码作业" 到 "我用 GitHub 做所有事", 这个转变工作量很小, 影响却很大.

## 12. 这不是终点, 而是一条主线的起点

到这里, "Learn GitHub Basics" 走完了打地基的部分. 但这远不是终点. 更准确地说, 你才刚刚踏上一条会贯穿整个职业生涯的主线.

这条主线的名字, 其实不叫 GitHub, 也不叫 Git. 它叫做: 用一个带版本控制和完整历史记录的系统, 把你所有的工作沉淀下来.

今天承载这条主线的, 恰好是 Git 加 GitHub. 它们好用, 免费, 全世界都在用. 但就算有一天 GitHub 不复存在 (以可见的未来来看, 这几乎不会发生), 也一定会有另一个系统接过它的位置. 变的是工具, 不变的是原则: 你日复一日留下的, 带时间戳, 可追溯, 谁都无法伪造的工作记录, 才是证明你自己最确凿的证据.

在 AI 时代, 这一点只会越来越重要. 所以别把这五节当成 "学完了一个软件". 你真正开始建立的, 是一份会跟着你走很多年的习惯和资产. 后面的课程会继续往前走, 教你怎么控制可见性, 怎么和别人协作, 怎么把这条主线用得更专业. 但从今天起, 主线已经在你脚下了.

## 13. 导师寄语

**为什么这个练习重要:**

这可能是整门课里价值最大的一节, 尽管它几乎没有技术内容.

我见过太多这样的情况: 学生学会了 Git, 会开 branch, 也能 push 代码, 转身回去却仍然用 Word 写所有东西, 把 GitHub 当成一个 "写代码的工具", 从而错过了更大的图景.

更大的图景是这样的: 在 AI 时代, 你的能力不再由你声称会什么来定义, 而由你能证明做过什么来定义. 而 GitHub 是唯一能提供无可辩驳的, 带时间戳证明的平台.

**关键洞见:**

- 主页上的一片绿, 比简历上任何一行字都更有说服力.
- GitHub 真正的威力不是版本控制, 而是上下文. 当 AI 能看到整个项目历史时, 它的能力会强上几个数量级.
- 养成这个习惯几乎不花额外成本, 因为那些活你本来就要干.
- 这对所有人都适用, 不只是开发者.

**下一步:**

从今天起, 每次打开 Word 或 Google Docs 之前, 先问自己一句: 这件事我能不能在 GitHub 上做? 答案几乎总是能. 做出这个切换, 让绿色方块自然积累. 半年之后, 你的 GitHub 主页会成为你简历上最有说服力的东西.

---

## 14. 速查

**每日习惯:** 打开你的 repo, 做你的事 (笔记, 作业, 文档, 代码), 用一句有意义的 commit message 提交, 完事, 绿色方块到手.

**关键链接:**

- 你的 GitHub 主页, https://github.com/YOUR-GITHUB-USERNAME-HERE, 用来查看贡献图.
- 你所有 repo 的列表, https://github.com/YOUR-GITHUB-USERNAME-HERE?tab=repositories, 从这里进入你自己的 repo, 它是你所有工作的大本营.
