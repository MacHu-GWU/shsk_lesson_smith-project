# 把整门课重写成英文的输入

> 用法: 把 `<repo>` 全部换成教学仓库的绝对路径, 其余原样照发. 整门课只跑这一次, 跑之前全部中文 (含根目录那三份) 必须已经写完并统稿过.
>
> 这份模板是自包含的, 供在一个全新会话里直接发起用. 如果你已经在 author 会话里, 直接说 "把这门课重写成英文" 就行, 它会按 [ref/rewrite-en-spec.md](../ref/rewrite-en-spec.md) 自己拼出下面这些内容.

/doc-writing-styles:rewrite-in-en-tutorial

把下面这些文件当作同一个系列一次性处理. 它们是一门课的全部正文, 互相引用, 术语与反复出现的小节标签必须跨篇统一. 为每份 `-cn.md` 产出去掉 `-cn` 后缀的同名英文版, 例如 `01-title/README-cn.md` 产出 `01-title/README.md`. 已有的英文版质量不佳, 无需留档, 直接覆盖.

```text
<repo>/README-cn.md
<repo>/TICKET-cn.md
<repo>/README-ORIGINAL-cn.md
<repo>/examples/README-cn.md
<repo>/examples/*/README-cn.md
<repo>/examples/*/TICKET-cn.md
```

## 1. 这个仓库有校验脚本, 下面两条会被它卡住

`lesson-smith lint` 会检查这些, 不满足直接报错. 请把它们转达给每个 drafter 和每个 rewriter.

**YAML frontmatter 保形.** 每份 README 与 TICKET 顶部的 frontmatter 要保留, `description` 的值翻成英文, 但形态不能变: 保持一行 (不含换行), 值必须用双引号包起来, 值里不许出现任何引号类字符 (单引号, 双引号, 反引号), 英文后不超过 800 字符 (这个 repo 的中文档是 400, 英文档是 800, 分档就是为了让你自然重写而不必压缩, 所以不要为了凑短砍内容). mini task 那些原本是 1 到 2 句的一行摘要, 英文版保持同样的紧度, 不要展开成一段.

**`README-ORIGINAL` 还多一个 `github_about` 字段**, 一行, 同样的形态约束, 英文上限 300 字符. 它比 description 紧得多, 因为那个上限来自 GitHub 的 About box 而不是我们的风格预算.

**H1 的字符集.** 每份文件的 H1 标题里, 除了字母, 数字, 逗号, 冒号, 句号以外不许有别的标点. 不许有连字符, 破折号, 引号, 双引号, 方括号, emoji. 这一条是 `markdown-style` 里的规则, 你们引擎转述那份规范时没有带上它. (`README-ORIGINAL.md` 的 H1 是唯一例外, 但那一份我跑完自己改, 你按你的规则重写它就行.)

## 2. 链接分两种

指向**文件**的相对路径链接换成英文版, 去掉 `-cn` 后缀. 这条你们本来就在做, 这里只是确认.

指向**目录**的相对路径链接原样不动. 各语种的文件都落在同一个目录下, 目录名本身没有语种之分, `examples/01-title/` 在中英两版里是同一个路径, 改了就是死链. 如果撞见目录名里带 `-cn`, 那是这个 repo 的存量命名错误, 报出来给我, 不要自己改成别的路径.

两份 `TICKET` 里本来就没有相对路径链接, 因为它们要进 GitHub Issue, 相对路径点不动. 重写时也**不要给它们新加**相对路径链接, 哪怕正文提到某个 mini task 看起来该链一下.

## 3. 不需要做的事

不需要做本地化替换. 这门课的中文版在创作时就已经用北美语境写了 (人名用 John Smith 一类, 公司产品场景取北美日常常见的). 如果确实撞见了漏网的中国烙印名词, 按你们自己的规则替换掉并在报告里说一声.

## 4. 不要做的事

不要把这批文件拆成多次调用. 跨篇的术语统一, 标题统一和交叉引用对账都只在一次跑动里成立, 拆开跑之后没有任何一步会补回来.

不要加 `--no-reconcile`.
